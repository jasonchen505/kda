模型报告成功，但代码可能错独立进程运行参考对照；先验证再计时未经正确性验证的候选不能晋升


失败后缺少下一步按数值、契约、编译、执行、协议失败生成反馈测试的具体失败信息进入下一轮提示

源码提案误触发工具调用接口层去掉工具声明；可选 JSON Schema 约束实际请求保留审计记录；标题请求不被重写


无限循环或重复提交3 轮上限、token/时间预算、源码去重终止原因写入轨迹，失败仍保留


优化后把正确版本弄坏保存此前通过验证的最佳候选后续失败不会覆盖已有正确版本


把旧测量套到新代码源码 SHA 与候选父子关系SHA 不符的“成功”证据被拒绝


平均更快，却丢掉满足性能门槛的候选正确候选先按门槛资格排序，再比较平均加速最终检查前保留合格候选；最终数据不参与重选


把调试结果当泛化结果选择完成后再跑一次独立最终检查最终失败能否决搜索阶段的晋升




JSON 正确，源码也可能错
实际预检返回了完整字段，但 Python 多行被拼接：
import torchimport tritonimport triton.language as tl
控制器拒绝它。不会自动拆开 imports 来制造成功。
把行边界写进协议
让模型输出字符串数组；控制器只按换行连接，保留每行缩进。
{"code_lines": [
  "import triton",
  "",
  "def example(x):",
  "    return x"
]}
这里只演示格式，不是生成实验或有效 GPU kernel。


这些改进位于下游 agent 控制器。它们没有修改模型权重，也不是 Humanize 内核的上游补丁。最新版本还检索固定版本的 MIT 许可示例，其中向量加法包含完整 kernel 与 wrapper。这属于示例辅助生成，不能声称无参考独立合成。源码准入是基本防错检查，不能替代完整的容器隔离或计算语义证明。
