02 · agent 本身改了什么

问题实现能验证的行为
模型报告成功，但代码可能错独立进程运行参考对照；先验证再计时未经正确性验证的候选不能晋升
失败后缺少下一步按数值、契约、编译、执行、协议失败生成反馈测试的具体失败信息进入下一轮提示
模型反复猜错 Triton API按任务选取固定版本规则卡与官方示例，保存来源和 SHA生成前与失败后都能收到可追溯参考
无限循环或重复提交3 轮上限、token/时间预算、源码去重终止原因写入轨迹，失败仍保留
优化后把正确版本弄坏保存此前通过验证的最佳候选后续失败不会覆盖已有正确版本
把旧测量套到新代码源码 SHA 与候选父子关系SHA 不符的“成功”证据被拒绝
把调试结果当泛化结果选择完成后再跑一次独立最终检查最终失败能否决搜索阶段的晋升

这些改进位于下游 agent 控制器。它们没有修改模型权重，也不是 Humanize 内核的上游补丁。最新版本还检索固定版本的 MIT 许可示例，其中向量加法包含完整 kernel 与 wrapper。这属于示例辅助生成，不能声称无参考独立合成。源码准入是基本防错检查，不能替代完整的容器隔离或计算语义证明。

05 · 复现的边界

已经执行

KDA 固定版本及子模块准备；Humanize 真实驱动本地 coding agent；生成任务与反馈循环；独立 GPU 正确性评测；正确候选进入计时与最终检查；可查看的完整轨迹。

尚未证明

没有运行完整 KernelBench。没有多次随机种子的置信区间。没有训练 kernel 模型，也没有证明达到领域最优性能。

当前 agent 通过结构化提案生成源码，由控制器写文件。它已按任务路由检索固定官方示例；尚未接入自主搜索、Nsight Compute 分析与开放式 shell 工具。KDA 提示是适配版，不是对原始完整研究流程的等价复现。

本次启动与接口问题
共享 27B 接口有请求排队；改用空闲 GPU 的独立 4B 接口。只读生成角色仍需要访问模型接口，因此不能把模型联网一并禁用。新服务首次启动使用了错误的缓存根路径，随后修正为 snapshot；采样器启动遇到本机编译工具问题，最终使用已有 vLLM 的旧 model runner 与非 FlashInfer 采样路径。所有这些记录属于环境与集成记录，未计入正式生成成功率。





06 · 求职展示怎么讲
可陈述的贡献是：基于 KDA 与 Humanize 实现本地 kernel 生成 agent，把候选选择交给独立评测器；加入反馈、预算、去重、回退和最终检查，并保留完整实验轨迹。对照结果以本报告真实计数为准。
已有普通反馈与 API 规则卡的同轮数对照；最新版本联合改进角色、示例与上下文。当前核心限制是小模型的 API 使用和修复可靠性。下一阶段应拆分这些改动做消融，再扩大到更多算子和多次种子。随后接入 KernelWiki 检索与 profiler，让优化建议来自实际瓶颈。只有新增对照结果支持时，才把“提高成功率或性能”写入简历。
