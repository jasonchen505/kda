# 生成与修复：对照结果

设备接入无效预跑已单独留档：48 次派发、3 次未确认响应。原生入口遗漏 CUDA 绑定，
已确认默认设备为 GPU0；这些结果不并入效果。修复将物理 UUID 绑定下沉到评测器，
正式 v2 使用新种子和独立账本，逐次核验子进程确实在 GPU4；策略源码保持不变。

## 最新主线：生成与修复的同起点交叉对照

新增两项可组合的 agent 策略：生成前在 draft/plan 中核对合约、输出坐标与内存偏移、
掩码和类型转换；修复时提供独立评测器产生的微型输入／预期／实际输出，结合失败
SHA 记忆与上下文允许时的正确版本锚点。源码仍由模型完整生成，没有人工修 kernel。

设计为 8 类任务 × 2 个新种子 × 2 种生成 × 2 种修复，**64/64 个最终结局已结束**。
32 个初始生成机会各执行一次，再把同一份源码和原始搜索裁决导入两种修复，每种
各两次机会；不是 64 个独立起点，也不是 192 次模型调用。实际派发 **152/160** 次。
所有组共享直连本地 Qwen 后端，去掉辅助标题调用，统一 8192 上下文与 2048 输出
额度。后端是公共实验设施，没有用旧 OpenCode 成绩计算因果加速倍数。

| 生成策略 | 修复策略 | 最终正确 | 条件性能门槛 |
|---|---|---:|---:|
| 普通 KDA 提示 | 普通错误修复 | 15/16 | 4/16 |
| 合约检查清单 | 普通错误修复 | 13/16 | 5/16 |
| 普通 KDA 提示 | 结构化反例修复 | 15/16 | 3/16 |
| 合约检查清单 | 结构化反例修复 | 13/16 | 5/16 |

首轮搜索正确：普通提示 **12/16**，合约清单 **11/16**。
首轮差异为 -6.2 个百分点，探索区间 [-50.0, 37.5]。完整流程最终正确的主效应：
合约生成 -12.5 个百分点，探索区间 [-43.8, 12.5]；反例修复 +0.0 个百分点，探索区间 [0.0, 0.0]。
先在任务内平均两个种子，再按八类任务重采样；不把 64 个结局当 64 个独立任务簇。
区间包含零的项目不支持稳定收益；所有区间均为小样本探索性描述。
本轮组合策略未提高最终正确数，不能把实现新策略写成已证实的效果提升。
保留普通生成＋普通修复为推荐配置；新增策略维持实验性，不因实现完成就自动晋升。
反例修复的 [0,0] 区间来自观测结果逐对相同，不是等效性检验。

共有 9 对共享初始失败，8 对充分观察；普通修复最终
救回 **5/8**，反例修复救回 **5/8**。初始正确案例不进入这个救回
分母，基础设施中断另列。端到端分母保留所有失败与未知结果。性能是 GPU4 当时
共卡环境下相对 torch.compile 的条件比值，数值和性能结论分别判断。

基础设施失败影响 1/16 个块，
不能直接将它造成的差异归因于提示策略。充分观察的
15 个块另作事后辅助计数：
双基线 15/15，
组合策略 12/15。
辅助子集不替换预定主结果，也不增加成功试验。

动态队列覆盖 **3 组生成 GPU、3 个进程身份**。先使用空闲副本，
再按观测延迟 EWMA 分配待运行块；同一块固定 API PID、启动时间与模型声明。
新服务可以接未启动块，已开始的对照不跨进程迁移，未知调用不重放。实际完成请求
峰值并发端口为 3；182 个独立 GPU 窗口峰值重叠
1。这些是调度证据，不是端到端吞吐提升倍数。

六类任务有开发历史；行均值和 LayerNorm 在策略冻结前定义。它们在设备接入无效
预跑中已有观测，策略未据此调参，但本轮不将它们宣称为盲测任务。跨目录权重等价性未核实，比较留在同一进程。
本轮没有见结果后改策略或重跑替换失败。原始候选、请求、响应、选择提交点与来源
都在 `results/repair-study/`；159 项机制与证据测试在两个 SDK 及新建锁定安装通过。

微型探针中，实际出现预期／输出矛盾 15 次，
探针通过 3 次；小样本通过不推翻原形状上的失败。
统计分析另作一项结果无关的兼容修正：旧区间函数只接受六类任务，本设计有八类。
采用加权多重集合精确表示全部 8⁸ 次重采样，保持原百分位定义，生成与评测源码未改。
修正决定早于首个正式块封存，旧分析脚本与新脚本分别冻结；未据此更换数据或策略。
无效预跑与正式运行共实际派发 200 次，保守分配 220 次；160 是正式实验额度。
