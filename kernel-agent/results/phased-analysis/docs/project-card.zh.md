# 求职项目：本地大模型 Kernel Agent Harness

**岗位方向：大模型算法／研究工程师、Agent Evaluation、AI for Systems。**

这个项目研究如何让 coding agent 可靠地生成、修复并选择 Triton kernel。KDA 提供
任务合约与草案工作流，Humanize/OpenCode 驱动本地 Qwen；我实现下游控制器、独立
评测、实验调度和证据链。六类算子是 agent 的评测任务。生成候选保留模型原样输出。

## 三项核心贡献

1. **可验收的 agent 闭环。** 逐行源码协议、基本 AST 准入、分类反馈、受限修复上下文，
   配合独立数值／性能评测、正确候选保留和新形状最终否决。最终数据不进入修复提示，
   也不参与重新选择。
2. **从负结果改进控制器。** 同预算反馈对照没有证明收益，轨迹却暴露平均排序会丢掉
   合格候选。修复为门槛优先；固定两份源码各做三次新进程重测，原选择 0/3 晋升，
   合格候选 3/3 晋升。后续真实生成的 3/3 正确、2/3 晋升单独记录，不冒称因果提升。
3. **让实验成果可恢复、可审查。** 源码与父 SHA、冻结计划、原子检查点、单写者锁、
   持久化预算和未知调用不重放；真实 SIGKILL 故障注入验证恢复机制。将生成与测量
   分阶段持久化后，复用已有候选完成两次共卡最终验收，新增模型请求为 0。保留在线速度反馈的新版中，
   搜索与选择先提交；真实 SIGKILL 后复用 6 条搜索测量，完成 2 次独立最终检查，
   新增模型请求与搜索检查均为 0。

## 最有用的面试案例

- **选择器错误：** 首轮平均 1.3366×、最差 0.773×，压过第二轮平均 1.3354×、
  最差 0.998×。把验收条件写进排序，避免“平均更快”掩盖严重回退。
- **最终验收：** 新共卡对照的向量加法在搜索形状达到门槛，最终形状仅平均
  0.936×、最差 0.812×，系统拒绝晋升。搜索成功不能代替最终验收。
- **资源调度：** 旧 36 次实验停留在 23 次终止。阶段分离保住已生成源码；独立共卡
  测量以 0 次新请求完成 5 次 GPU 检查，两次最终均正确且达到共享性能门槛。

共卡速度是当时环境下相对 `torch.compile` 的比值。新六任务、两组、一个种子的
12 次真实反馈对照已全部终止：无反馈 6/6 最终正确，有反馈 5/6，两组均 1/6 晋升。
一次 900 秒预算停止没有最终裁决，保留源码与分母；本轮未证明反馈收益。

最新阶段恢复试跑：转置、Softmax 共 6 份真实提案，最终 2/2 正确、1/2 晋升；
119 项机制与证据检查通过。该试跑验证恢复路径，不与旧对照合并估计收益。

## 五分钟审阅路径

1. `reports/kernel-agent-report.html`：项目主线、架构、完整对照、真实轨迹。
2. `flows/kernel_loop.py`、`src/kernel_agent/protocol.py`：生成、反馈与验收闭环。
3. `src/kernel_agent/campaign.py`、`src/kernel_agent/deferred.py`：预算、恢复与阶段分离。
4. `python3 scripts/verify_evidence.py`：离线核对冻结源码、实际请求、候选及裁决。
5. `docs/project-summary.zh.md`：简历文字与三分钟面试叙述。

项目已适合作为有实证的 harness 原型写入简历。它使用固定官方例子辅助生成；任务族
参与过开发，尚不能说明未见任务泛化。基本 AST 检查不是安全沙箱；单次种子对照和
共享测量也不能估计稳定成功率或独占性能收益。工程测试与真实模型实验分别计数。
