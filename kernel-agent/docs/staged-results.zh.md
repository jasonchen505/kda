# RTX4090 多阶段 Kernel Agent：移植与经验迁移

2026-10-17。研究对象是写 kernel 的 agent。新增真实 Humanize SDK 多阶段路线，
没有手工修补模型候选，没有修改 Humanize 上游核心，也没有把 4090 开发任务写成
B200／FlashInfer 比赛流程的完整复现。本文的最终计数以配套派生汇总为准。

## 三条路线如何比较

```text
任务合约／冻结预算 → 三路本地 Qwen 按配对块分配
  ├─ fixed：完整源码提案 → 自动搜索评测，最多六次提案
  ├─ staged：研究做对 → 诊断迭代 → 形状比较
  └─ staged_transfer：相同阶段 + 部分源码事实／数值解释／SHA行号补丁

多阶段内部：独立草案调用 → 独立计划调用 → 模型选择真实工具 → 新会话审查
共同交付：三个策略均提交搜索选择 → 独立最终验收，只接受／否决，不回传重选
```

三组都经过实际 Humanize → LiteLLM → 审计网关 → 本地 Qwen，并非只给 JSON
字段起了角色名字。每次角色调用创建新会话，宿主保存源码和证据；没有保留原插件
中的长会话 writer。研究阶段至多六次工具动作，后续每阶段四次；规划和审查也消耗
总计24次模型机会。每组同为六次提交、九次搜索评测、两次 profiling 上限。
固定组通常只用六次模型调用。**上限相同不代表实际推理成本相同**；这也是工作流、
工具权限和审查共同变化的对照，不能单独归因于“先规划”。

任务为仿射 SiLU、缩放转置、L2 归一化，均是已经用于开发的任务族；每轮三个
配对块、一个种子、九个结局。同一块三组固定在同一服务进程；跨服务的权重相等
未经验证。三路服务可以并行生成，本项目 GPU4 评测和追踪串行，共卡允许。
性能比值是共享环境中的条件观察。

## 原方法和本项目的经验分别迁移了什么

| 经验来源 | 本次实现和实际证据 | 迁移边界 |
|---|---|---|
| KDA：分阶段、先调查再计划 | 单独保存草案和计划，writer 主动选择读取／检索／提交／评测 | 保存计划不保证计划在工具和行动预算内可执行 |
| Humanize：执行与审查 | 真实 SDK agent、LiteLLM、typed output；新会话 reviewer 引用宿主事件 | 同一 Qwen 的不同上下文，不是 Claude／Codex 异构审查，也不是原 RLCR 插件重放 |
| KDA：基于 profiler 迭代 | NCU2024.1.1 真正尝试采集，权限拒绝原样保留；降级为真实 CUDA 活动追踪 | 没有 SM／DRAM／stall 计数器，不能恢复完整瓶颈归因 |
| KDA：领域知识检索 | 可查询固定 KernelWiki，另可读 Triton3.2 API 和示例 | 当前只是字面检索，未接入上游 query.py；原知识库偏 Hopper／Blackwell，Ada 适用性需核实 |
| 本项目：可信反馈和源码修复 | 原样保留被拒源码、有限数值／坐标证据、部分源码事实、SHA绑定的原子行号补丁 | AST 观察不是数值证明；补丁工具可用不等于模型实际使用或修复成功 |
| 本项目：成本与资源控制 | 真实分词预算、持久化派发、未知调用不重放、三路服务准入／调度、UUID绑定 GPU4 | 该多阶段路线不恢复任务内部 Humanize 会话；中断块记未知，不重跑获分 |
| 本项目：独立选择和验收 | 搜索候选按门槛优先保留；三组先提交 SHA，再读取最终数据 | 阶段通过与最终正确／性能晋升分别计数；没有用最终结果挑另一个候选 |

## 首轮缺陷与独立修正轮

首轮 `staged-study-v2`（seed2026101701）最终正确为固定3/3、基础多阶段1/3、
增强多阶段0/3，均无性能晋升，共68次实际模型调用。六条多阶段轨迹均被拒绝在研究
阶段。至少一个已有正确 GPU 结果的研究阶段，被 reviewer 错误要求完成未来的形状
比较；审查包还隐藏了真实读取／检索事件。增强组没有源码事实派发，也没有补丁调用，
不能据此认定修复机制无效。另一个已完整收到的截断源码回复使 SDK 直接终止固定组。
详情见[原始缺陷分析](staged-initial-diagnostics.zh.md)。

另立 `staged-study-v3`（NEW seed2026101702），修正阶段专属条件、完整工具事件
可见性和空源码错误提示。只有已完整接收、响应哈希匹配的无效 writer 回复，才允许
消耗当前动作后继续使用剩余动作；不拼接残缺源码，不重放未知请求，不增加次数。
两轮结果分别保存，不替换、不合并；跨种子变化也不是修正的干净因果效应。

## 失败轨迹说明了什么

基础组的仿射 SiLU 和 L2 已通过研究阶段，却在诊断阶段没有完成计划中的变体实验。
实际工具轨迹是 profiling、读取／空检索、再次 profiling，然后申请审查；没有按计划
提交并评测新的变体。拒绝体现的是实际未完成计划，而非缺少一个好看的 reviewer 分数。

这些计划本身也有可执行性问题。仿射 SiLU 计划使用工具集中没有的 `write` 和
`benchmark`，列出的动作多于四次预算；L2 计划要求 memory throughput、occupancy
和 stall reasons，而环境只提供 CUDA 活动降级信息。这是**计划与工具／预算能力的
契约还没有闭合**。仅增加 planner、reviewer 或工具说明，不保证模型执行有效优化。
失败可能同时涉及模型决策、计划质量与宿主接口，本轮不能把它们单独做因果归因。

增强组的审查也不总可靠。仿射 SiLU 的 reviewer 把带 instrumentation 开销的 CUDA
活动时长和另一次独立计时混比，声称已确认 launch overhead；这个结论不成立。
L2 的 reviewer 又把无硬件计数器列为缺失的一部分，尽管本轮允许显式降级。
宿主保留这些原话作为失败证据，报告不采纳它们作性能归因；同模型的新会话审查不能
替代独立测量或能力契约。

还有参数层面的失效：L2 增强组在已成功 profile 后，两次把字符串 `latest source SHA`
当作真实 SHA 传入。宿主拒绝了不存在的源码，但返回空错误消息，未帮助模型纠正。
缩放转置则反复读取尚不存在的生成源码，没有形成及时提交／评测。二者说明失败记忆
和下一步工具提示仍需改进；本轮保留实际损失的动作，没有事后追加机会来补分。

额外做了零模型／零GPU调用的检索诊断：三条首轮零匹配查询，用原 KernelWiki
`query.py` 各返回两页。返回页面未验证相关性或 Ada 适用性，也未回灌正式 agent。
它表明检索适配需要进一步核对，不能写成检索增强已提高生成成绩。

形状阶段的程序门槛只校验不同源码 SHA、正确搜索结果、至少三个形状和实际引用；
它不证明两份源码有不同语义或存在有效路由。完整三阶段的合成测试验证的是接线和
最终数据隔离，不能代替真实模型完成阶段。数值正确性仍以独立 GPU 程序为准。

## 求职叙述与交付

可以陈述：在 RTX4090／本地 Qwen 上实现基于真实 Humanize SDK 的分阶段 Kernel
Agent，将规划、工具执行、证据审查与已有可信评测／预算修复机制接通，并通过独立
对照保留负结果，定位阶段目标串扰、工具可见性、协议恢复和计划可执行性问题。

不能陈述：完整复现 KDA 比赛、改造 Humanize 核心、证明多阶段优于普通修复、稳定
泛化到外部 kernel benchmark，或通过 CUDA 活动追踪获得了硬件瓶颈计数器。
普通生成／修复仍是默认路线；多阶段移植作为可审计的实验入口保留。

两套环境的236项 CPU 工程检查和 lint 均通过，包含拒绝伪造证据、错误补丁保留父版、
重复网关票据拒绝、已知无效回复的预算恢复，以及三阶段合成接线。测试驱动不计模型
成功。所有新增原始请求、源码、完整计划、测量、trace 和冻结文件都留远端。
