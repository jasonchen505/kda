# 求职项目主线：有实验依据的 Kernel Agent

定位：大模型研究工程与 AI for systems。研究对象是生成、修复并选择 Triton kernel 的
agent；GPU 算子是用于验证这个系统的任务，不把手写算子结果算成 agent 成绩。

## 面试叙述

1. 问题：coding agent 可能声称成功、反复提交同一源码，或把优化后的错误版本当结果。
2. 复现：适配 KDA 的任务与草案工作流，用 Humanize/OpenCode 驱动实际本地 Qwen
   会话。没有付费 API；不是完整 KDA 研究流程的等价复现。Humanize 后续已更新，
   受测旧源码与环境独立保留，当前控制器兼容新旧两版 API。
3. 改进：实现独立数值/性能裁决、分类反馈、预算停止、源码 SHA、正确候选保留、
   新形状最终否决，并对生成协议和修复上下文做了诊断与修复。
4. 验证：把模型能力试验、同模型策略对照和未参与前期开发的新任务分开，保留正负
   结果。等提案预算比较有无评测反馈，并审计首轮、末轮和搜索最优的选择结果。
5. 交付：可执行控制器、GPU 评测器、固定实验计划、原始轨迹、源码快照和离线 HTML。

## 主线进度

- 已完成：真实 agent 会话、四类任务的正确性/性能流水线、4B 接口消融和表示消融。
- 已完成：缓存 27B 模型能力试验，四项最终正确，Softmax 单项性能晋升；不能将
  跨模型差异归因于控制器。
- 已完成：同模型、每组每任务三个提案机会的有无反馈对照。两组各 3/3 最终正确、
  0/3 最终晋升；提前保留的 row_sum/silu_mul 在两组各 2/2 正确。每条件一次。
- 发现并修复：按平均搜索加速排序会丢掉满足性能门槛的候选。SiLU 反馈组第 2 轮
  搜索平均 1.3354×、最差 0.998×，被平均 1.3366×、最差 0.773× 的首轮覆盖。
  第 2 轮最终为 1.287×、最差 0.990×，通过验收，却没有成为原运行输出。
- 修复规则：正确候选中先比较是否满足已有性能门槛，再比较平均加速；最终检查仍
  有否决权。流程回归通过。在原候选集上的事后审计为反馈组 1/3 晋升、无反馈 0/3；
  没有重新生成，不改变原实验 0/6 成绩。固定候选三次新进程复核中，原选中候选
  0/3 晋升，被丢弃候选 3/3 晋升（1.289–1.299×）；这支持测量稳定性，不证明修复
  后 agent 的稳定收益。
- 接下来：扩展任务难度与独立种子，再引入实际编译器/profiler 反馈，验证它是否比
  纯延迟反馈更有效。稳定成功率、广泛性能收益和通用基准成绩仍需实证。
- 已补完：修正规则的三次真实生成复现，3/3 最终正确、2/3 晋升。SiLU 平均
  1.291×、RMSNorm 1.073×；行求和 0.949×，未晋升。SiLU 第二轮重建出选择分歧，
  第三轮后新旧规则最终选择相同。推理服务配置改变，没有无反馈对照；不能把
  这次成绩写成选择器单独带来的成功率提升。18 份受测文件、9 份候选、9 次提案
  请求已逐项核对，本轮与原始六次对照分别保存。

## 可量化贡献怎样写

简历先写实现与可复现的测量口径，再填具体实验数字。例：
“实现基于本地 Qwen 的 Triton kernel agent，搭建独立数值与性能评测、分类修复和
候选选择闭环；完成同预算反馈对照与两类新任务验证；从轨迹定位并修复平均排序与性能门槛不一致的候选选择缺陷，交付完整实验报告。”

任何成功率都必须带任务数、模型与参考条件。Softmax 的 1.235× 是三种 BF16 输入
相对编译参考的加速几何平均，不是端到端模型推理加速。“逐行协议 0/12→9/12”是
基础源码准入观察，不是 GPU 正确率提升。54 个机制与接口测试验证控制器行为，不是模型生成成功。
