# 从退步结果提出可检验的修复机制

研究对象是 kernel agent 的生成、审查和修复流程。以下判断基于已封存源码与真实回复，
没有人工改 kernel，也没有把追加重试覆盖到旧实验。

## 上一轮的差距来自哪里

完整配置（合约生成＋反例修复）最终正确 13/16，普通生成＋普通修复 15/16。
逐块比较可把净差分解为三次算法失败和一次反向的基础设施差异：

| 配对块 | 普通配置 | 完整配置 | 原始证据 |
|---|---|---|---|
| SiLU，20261102 | 最终正确 | 未通过 | 合约初稿漏乘 x，两个修复都未补回 |
| 转置，20261101 | 最终正确 | 未通过 | 错误输入行步长及二维存储索引，修复后仍错 |
| 转置，20261102 | 最终正确 | 未通过 | 广播轴与存储坐标不对应；修复包含新编译错误 |
| 行求和，20261102 | 未通过 | 最终正确 | 资源监视超时中断后续调用，不归因于提示策略 |

因此“少两个正确”不能全解释为算法退步幅度。预定结果保留全部 16 块；充分观察的
15 块中，普通配置 15/15，完整配置 12/15。这个辅助计数仍不是独立的新实验。
首轮普通提示 12/16、合约清单 11/16；反例修复在 8 个充分观察的失败配对中，
与普通修复同为救回 5 个。原始记录见 `results/repair-study/`。

## 三个有源码支持的问题

**数学因子没有落实到代码。** SiLU 需要 `x * sigmoid(x) * y`，初稿只计算
`sigmoid(x) * y`。修复会更换 API、改写变量，却保留相同数学错误。有一次文字已经
说出完整公式，源码仍漏因子。失败 SHA 只能发现逐字重复，不能发现换写法后的同一错误。

**布局推导可写对，索引实现仍不对应。** 两个转置失败都来自合约生成；实际出现输入
行步长混用 M/N、偏移广播轴与载入值不对应。修复文字会写“交换坐标”“正确步长”，
但后续源码仍未通过数值检查。非方形、非对称输入能暴露这些错误；只展示一段计划
不能证明实现正确。

**解释没有经过证据约束。** SiLU 的失败样本为 FP32，修复却曾归因于 BF16 精度。
另有 RMSNorm／LayerNorm 初稿把 torch.dtype 当作 Triton 内核 `.to()` 的类型参数，
属于编译接口问题。数学检查和类型/API修复需要分别记录，不能用一个数值解释概括。
两个行均值初稿还将输出指针按输入宽度移动，直接体现了输出形状与存储步长脱节。

这些轨迹说明当前流程缺少对解释与数值证据的核对，不能证明模型内部的注意力机制。
“清单引导模型过度关注布局而忽略公式”只是可能解释，现有实验没有测量内部因果路径。

## 本轮改变 agent 的哪一层

增加独立审查步骤，要求返回参考表达式、候选表达式、故障假设和修复计划。控制器用
受限 AST 解释器运行表达式，在两组完整、非对称 FP32 搜索探针上核对形状和数值。
输入包含不同负值和不同因子；所有值完整保留，避免只看前几个相同元素。

核验组只接收通过核对的表达式、核验轨迹及可信探针；未核验的自由叙述与计划不进入
这部分上下文。表达式拒绝时提供事实性回退，不给模型追加一次机会。编译失败导致
候选输出不可观测时，记录不可核验，不能臆造通过。实际 kernel 仍需原有独立评测。

对照分为连续重写、原始审查、核验审查。后两组共享同一份审查响应，从而观察过滤和
数值核验的增量作用；第一组比较两次机会用于重写和用于审查的预算分配。后两组各
只有一份新 kernel，不能声称控制了 kernel 候选数量。具体协议见
[semantic-study-plan.md](semantic-study-plan.md)。

机制预检在物理 GPU4 上将 16 个算例与 Torch 参考对照，并运行原封不动的错误 SiLU
与正确加法候选。预检不是 agent 成绩。首次候选启动因 PYTHONPATH 缺失而失败，
保留在 `results/semantic-smoke/startup-invalid-no-model.json`；修正启动环境后重做，
未消耗模型调用。机制证据见 `results/semantic-smoke/`。

## 这项机制仍有什么边界

有限探针匹配不是符号等价，也不覆盖全部布局、掩码、宽度和 BF16 舍入。审查员还
可能不能遵守表达式语法；严格拒绝能避免将错误意见称为已核验，但可能减少可用指导。
核验参考式也不保证新源码落实了它。这些都是新一轮真实对照需要回答的问题。

新实验的已知失败回归和新生成验证分开报告，不使用它们替换旧负结果；最终结果与
策略选择见 `semantic-study-results.zh.md` 和 HTML 的语义修复章节。
