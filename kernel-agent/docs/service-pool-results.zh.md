# 三路服务池：结果与求职表达

## 最新工程验证：多服务并发与入口失效恢复

将自建本地 Qwen 与两个获准空闲使用的服务接入 harness。每个服务有独立进程、
工作区、代理和账本；请求前检查模型声明、空闲指标与实际分词长度。三路共同使用
8192 上下文、每请求至多 2048 输出 tokens。GPU4 上本项目的评测通过可继承文件
描述符的锁串行执行；允许其他用户共卡，保留设备遥测。

本轮六类任务、两个新种子、两组策略，**24/24 已结束，最终正确 20/24，
条件性能门槛通过 6/24**。69 条提案机会记录中，
实际发出 67 个提案请求，提交 66 份模型回复及 66 份准入候选；
重复源码也保留，不把机会数当成功数。三个提案端口的完成请求区间曾同时重叠；
80 个已知独立 GPU 评测窗口的峰值重叠为 1，未测得端到端并行加速倍数。

| 条件 | 已结束 | 最终正确 | 条件性能门槛 |
|---|---:|---:|---:|
| 无评测反馈 | 12/12 | 10/12 | 3/12 |
| 实际搜索评测反馈 | 12/12 | 10/12 | 3/12 |

两个借用入口在中途失效。记录新端口的声明与物理 GPU 映射后，以单独冻结的网关
恢复逻辑入口。**复用 15 项提交结果，只继续 9 项未启动任务**；178 份已有请求／
准入文件保持原 SHA，预算未重置，已完成任务没有新增模型请求。4 项转置均无合格
候选：3 项数值失败、1 项接口异常，均未启动最终检查，保留在端到端分母中。
共有 3 项因接口异常提前停止，其中 Softmax 与 RMSNorm 仍复用已有正确候选完成最终
验收，转置没有可用候选。两份请求未确认完整响应；代理隔离该任务后不再向上游转发重试，不能声称外部调用
恰好一次。SDK 已报告输出量与服务端未知用量分别解释。

五对策略任务跨越服务进程重启，整轮反馈收益与区间关闭。以上是并发、预算和恢复
机制的真实工程覆盖，不证明反馈改善 kernel 质量；服务版本不同、跨目录权重等价
性未核实、缓存连续性未知，也不作跨服务质量比较。旧实验保持独立口径。

可离线核对 `results/pool-study/`、`results/pool-before-handoff/`、
`docs/service-pool-handoff.md` 和报告的“服务池对照”。当前 **134 项**机制与证据
测试通过两个 SDK 及新建锁定安装；测试数量与真实模型／GPU 数量分别计数。

## 简历里可说与不能说

可说：多服务并发、请求准入、统一额度、GPU 协作串行、阶段持久化与中断恢复；
原始失败与未知结果可审计。不能把 3 个并发端口写成 3 倍吞吐，也不能把性能比值
写成端到端大模型加速；当前结果没有证明反馈优越性、未见任务泛化或生产安全性。
