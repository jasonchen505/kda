## 三类可重建的失败

1. **未来阶段条件泄漏到当前审查。** 仿射SiLU基础版有真实正确搜索结果和活动追踪，
   研究阶段却被要求提供两份正确源码、三形状比较和分派决策。这些是第三阶段条件。
   失败来自不清楚的阶段接口，不能归咎于外部服务或GPU干扰。
2. **工具确实调用了，reviewer却看不见。** 审查包只保留evaluate/profile事件。
   归一化与转置的读取／检索记录被省略，于是出现“没有任何工具事件”的错误诊断。
   其中有失败读取和零结果查询，它们不算研究成功，但应如实呈现为已执行的失败。
   新工作区还缺少“尚无源码，应先读api/example或submit”的可操作错误信息。
3. **完整收到坏回复后提前放弃预算。** 归一化固定组第二次回复在2048输出上限截断，
   原始接收状态为completed、结束原因为length。SDK类型解析失败终止了该组，只有
   两次实际调用，尽管仍有剩余机会。正确旧候选仍被保留并最终通过；没有拼接坏回复
   来制造新源码。新接口只对完整接收且哈希匹配的格式错误开放预算内下一次机会。

## 独立修正，而非改写结果

`staged-study-v3` 使用新种子2026101702及另一个账本。按阶段发送验收条件；reviewer
可见真实读取／检索／失败事件；保留坏源码并区分已收到格式错误与未知请求。三组的
调用、输出和候选上限保持不变。它不是往旧实验补结果，也不把两个种子的差异当成
单独修正的因果效果。修正后的三组对照仍是小样本组合干预。
