# 修正规则的新生成验证

2026-10-12 完成。研究对象是 kernel agent 的候选选择与验收路径。生成代码未经
手工修改，原始同预算反馈对照与固定候选复测均保持独立。

| 任务 | 提案机会 | 最终正确 | 最终平均加速 | 最差形状 | 晋升 |
| --- | --- | --- | --- | --- | --- |
| SiLU 乘法融合 | 3 | 通过 | 1.291× | 0.968× | 是 |
| RMSNorm | 3 | 通过 | 1.073× | 0.954× | 是 |
| 行求和 | 3 | 通过 | 0.949× | 0.851× | 否 |

三个任务各运行一次，均为既有任务族。九次提案产生九份不同 SHA、零重复，全部
通过搜索正确性检查。每份搜索正确源码均有一次最终评测，实际选中候选先接受
最终检查；其他候选的最终数据仅供审计。三项选中输出各通过 28 项最终检查。
平均加速是三个 BF16 形状相对 `torch.compile` 参考的几何平均；晋升门槛为平均
至少 1.05×、最差形状至少 0.90×。不是模型推理的端到端加速。

实际输出 6082 token，流程总计 1985.0 秒，包含搜索评测和其他候选最终审计。
推理排队与服务配置未严格控制，耗时不能与原对照作因果比较。

## 修复分支是否真的出现

SiLU 前两轮的搜索证据：

| 轮次 | 搜索平均加速 | 最差形状 | 搜索资格 |
| --- | --- | --- | --- |
| 1 | 1.3395× | 0.7925× | 不满足门槛 |
| 2 | 1.3316× | 0.9995× | 满足门槛 |

只按平均选择会保留首轮；门槛优先会保留第二轮。这个中途分歧可从记录的搜索
证据与受测选择函数重建，重建不使用最终数据。第三轮调整了 launch 配置，成为
两种规则共同的最佳候选。完整三轮后的新旧规则在三项任务上均选择相同源码。

因此，本轮验证了修正规则的真实生成路径，最终选择 SHA 也与门槛优先排名
逐项一致；不能声称它单独带来这次 2/3 晋升，更不能将原始 0/6 改写成提升成绩。
原始失败分支的确定性流程回归、固定源码复测、新生成复现分别回答不同问题。

## 运行与证据边界

使用缓存 27B FP8 Qwen，实际配置 `qwen3_5`；目录名是本地别名，上游权重版本
和全量权重 SHA 未核实。温度 0、seed 20261012，每请求最多 4096 token，
每任务三个提案机会和 900 秒/20000 输出 token 预算；固定官方参考与逐行协议。

GPU4/5 被占用后，复用用户自己的空闲基础模型服务（port 8016、生成 GPU2/3）。
请求明确使用 `qwen38-27b-fp8`，不请求注册的 LoRA。该服务的上下文上限、FP8 KV、
前缀缓存、LoRA-enabled runtime 与原独立服务不同。评测始终在空闲 GPU6 上完成。
它是三次端到端复现，没有无反馈组、独立新任务或多种子统计。

- `results/agent-selector-validation.json`：三次完整运行，SHA
  `ead614f0f5fbf25e8a743790539b68e4749e037c689bfdb845f72616e029543f`。
- `results/selector-runtime-manifest.json`：服务进程、配置、基础模型列表、初始队列
  和 adapter 路由实现的源码指纹。
- `results/selector-validation-delivery-audit.json`：18 份受测文件、9 份候选的实际
  文件、最终 SHA 绑定、原始模型提案无改写、9 次提案请求和 9 次背景请求的核对。
- `results/study8-measured/` 与 `results/study8-analysis/`：受测实现和报告分析快照。
- `reports/kernel-agent-report.html`：离线图表、逐轮轨迹和完整 JSON 下载。

执行入口：`bash scripts/reproduce_existing_selector.sh 8016 3097365`。服务 PID 随
重启变化；入口先检查所有权、模型与空闲状态，拒绝已有结果，结束只关闭自建代理。
完成后运行 `scripts/audit_selector_validation.py`。独立服务入口仍为
`bash scripts/reproduce.sh selector-validation`，需要可用的 GPU4/5。
