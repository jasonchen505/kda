# Local Qwen Kernel Agent Harness

A portfolio research engineering prototype about the agent that writes kernels. Reuse
KDA's workflow references and an early Humanize/OpenCode integration, plus Qwen and Triton; downstream contributions are source-grounded,
budgeted repair, independent evaluation/selection, durable recovery, three-service scheduling
and reconstructible experiments. Candidate kernels are never hand-repaired.

The new RTX4090 port adds real Humanize SDK planner/writer/reviewer execution through
LiteLLM and an audited local Qwen gateway. Separate drafting/planning precedes typed,
model-selected read/research/submit/patch/evaluate/profile tools and evidence-citing review.
Existing source memory, bounded repair, tokenizer admission, three-service scheduling and
selection-before-final acceptance carry over. Every role turn is fresh with host-managed
memory. The original persistent CLI writer and Claude/Codex RLCR plugin are not reproduced.

See [migration results and costs](staged-results.zh.md),
[execution/audit](staged-reproduction.md), and [HTML](../reports/kernel-agent-report.html#staged-study).
Phase completion, final correctness and performance promotion are separate endpoints.
The corrected cohort ends with fixed3/3, staged2/3 and transferred2/3 final-correct,
using18/41/40 calls respectively. No performance promotion or full three-stage completion;
source facts enter15 requests, but no patch actions are used. The first68-call cohort's
interface defects remain separate. Three development families/one new seed and bundled
workflow changes do not establish a general effect or isolate planning's contribution.
Permission-denied NCU counters remain explicit; real CUDA-activity fallback does not provide
SM/DRAM/stall evidence. Ordinary repair remains default, staged variants experimental.
No Humanize upstream core changes or equivalent B200 contest reproduction are claimed.

236 CPU checks and lint pass in controller and isolated SDK environments, including full
three-phase synthetic wiring. These are mechanism tests, not generated-kernel successes.

The initial study dispatched56/64 calls. New feedback overflowed two contexts and wrongly
stopped the counterpart. Keep that ledger; do not relabel it as external GPU interference or
replace failures. The follow-up tokenizes actual histories/modes, chooses full/compact/baseline
context views, and isolates policy budget failures. It dispatched24/24 calls.
The preceding release passed219 CPU mechanism/evidence checks and lint, including forced policy-local refusal.
Fake-driver tests are not agent successes. Real evidence retains source/process/GPU identity.

The previous indexed/fallback comparison separately recorded13/14 known-failure correctness,
versus9/14 rewriting and7/14 text patches; all recent-family fresh-start arms were6/8.
Small development samples and task-cluster intervals do not establish external generalization
or equivalence. Keep ordinary repair as default; new policies stay experimental.

No paid model API is used. Three authorized Qwen services use idle admission/EWMA, pinning
one process per pair. GPU4 sharing is permitted; project evaluations are serialized and
physically UUID-bound. Timing ratios are conditional, not isolated or end-to-end speedups.
Raw requests/replies/kernels/measurements/freezes remain remote outside Git/Mac. Public
summaries check self-hashes/counts; full raw reconstruction requires server access.
