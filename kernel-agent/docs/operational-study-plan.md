# Prospective comparison: operational evidence and transactional repair

Freeze policy, evaluator, task definitions, capability inventory, bank and call cap before
any new model proposal. Prior semantic-review and factorial results remain unchanged.
This iteration tests an agent repair architecture, with no human-authored kernel fixes.

## Why change the workflow

Previous mathematical review admitted only 8/22 reference expressions and did not improve
final correctness: all arms 7/14 known-failure regression, 7/8 fresh starts. A correct
review still allowed unsupported API inventions or wrong pointer/mask axes. Incorrect
reference mathematics was rejected but not repaired. Unverified free-text filtering alone
does not enforce an actionable code change and consumed one of two model opportunities.

The new controller derives observable repair obligations directly from trusted search
probes, without a task-ID answer table or additional reviewer request. It identifies
simple expected-versus-actual algebraic relations across BOTH asymmetric probes; detects
finite permutations of an input or input product and emits unique-value coordinate/flat
offset witnesses; routes actual API/compiler, layout, algebraic and other failures.
These are finite-probe descriptions, never symbolic correctness proofs.

The model emits 1..4 exact before/after line edits against the retained source SHA.
The controller applies all edits atomically against that original source, rejects missing,
ambiguous, overlapping, stale or invalid-source transactions, and never invents a patch.
A rejected patch consumes its attempt and retains the last admitted source for the next
attempt. If no admitted source exists, the same slot becomes full-source recovery.
API availability uses a frozen inventory read from the installed Triton 3.2 environment.
Both arms' candidates share the same direct-symbol preflight and full GPU evaluator;
preflight admission is not compilation/type/numerical proof. No manual kernel edits.

## Two paired policies and budgets

- `rewrite`: two ordinary complete-source revisions with raw evaluator feedback.
- `operational_patch`: two model-authored patch transactions with typed obligations,
  trusted complete probes, failure memory, source anchoring and installed API inventory.

Each arm receives TWO calls, each at most 2048 output tokens. No model review call is
added. Initial generation is plain and shared byte-for-byte with the same new search
verdict. This is a bundled architecture comparison: representation, routing, anchoring
and evidence differ together; it does not isolate individual components. GPU work may
differ because protocol/API failures avoid execution and exact-source measurements reuse.

At each repair round, arm order is seeded and randomized. Initial seed=s; both arms'
round1 seed=s+1 and round2 seed=s+2. One process fingerprint per block; no sibling source,
feedback or final data enter the other arm. Commit both search selections before either
final evaluation. Final results accept/veto the chosen SHA, never trigger reselection.

## Independent strata

Known failures: use ALL seven admitted, non-infrastructure initial failures from the
original frozen factorial bank, selected by initial verdict/source only. No filtering on
repair outcomes. Five task families, repair seeds 20261121/20261122, 14 blocks and
28 terminal arm outcomes. Imported source is re-evaluated once before both arms; any
unexpected success or infrastructure result stays visible.

Transfer: FOUR newly defined families in `repair-transfer-tasks.json`: column reduction,
row L2 normalization, affine SiLU, and column-scale plus transpose. Two generation seeds
20261123/20261124, eight shared initial proposals, eight blocks and 16 outcomes. Definitions
and evaluator are frozen before first model use. They are prospective new families within
this project, not an external blind benchmark. Oracle/mechanism smokes use no model or
handwritten candidate; they are separate from agent results. Final shapes remain private
to the independent evaluator and are never included in repair evidence.

Total: 22 paired blocks, 44 terminal outcomes, ceiling **96 physical dispatches**:
14*4 + 8*5. Reserved output ceiling 196608 tokens, not measured usage. Unknown requests
are never replayed; per-block allocations persist even when later opportunities do not
run. Source/protocol/API failures and infrastructure failures are separately retained.

## Runtime and decisions

Use the three authorized local cached Qwen services through dynamic idle discovery and
latency-EWMA dispatch, common8192 context, temperature0.2, no tools/no thinking, output2048.
No foreign service edits/restarts or paid API. Retokenize complete contexts; mandatory
source/evidence cannot be sliced. Active blocks never migrate across processes. GPU4
allows sharing; project evaluation is cooperatively serialized with child UUID proof.
The old evaluator's original eight task paths/criteria stay unchanged; new families use
its same dtype, mutation, contiguity, numerical and timing protocol with new frozen oracles.

Primary: all14 regression final-correct outcomes per arm, paired difference averaged
within each of FIVE families. Secondary: separate transfer8/arm, average two seeds within
FOUR families. Exact task-cluster bootstrap intervals are exploratory; zero width is not
an equivalence test. Conditional rescue excludes initial successes and reports fully
observed/no-infrastructure cases separately; no replacement of planned denominators.
Report patch admission/error causes, API rejections, call/output use, independent GPU work,
retained-source recoveries, exact code lineage and representative successes AND failures.

Retain prior default on null/negative outcomes. Even positive development-set gains need
new external tasks/more seeds before a broad claim. No tuning or retry to replace a
negative result after this freeze. Publish honest results, HTML, resume notes and evidence
on the existing independent branch.
