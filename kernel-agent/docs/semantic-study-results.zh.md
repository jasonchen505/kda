## 真正改变的机制

独立审查员返回参考式、候选式及自由叙述。受限 AST 解释器在两组非对称 FP32 搜索
探针上计算并核对形状、数值。8/22 个块的参考式通过；候选式通过 4/22（未执行也保留为未通过）。
拒绝原因按审查记录计：9 份不支持的语法、3 份数值不符、2 份结构化审查不合规。
核验组只接收已匹配表达式、检查轨迹和可信探针，过滤未核验叙述；拒绝后事实回退，
不增加模型调用。有限探针不证明符号等价、BF16、布局或完整 kernel 正确。

连续重写组有两份新 kernel；审查组各有一份新 kernel，另一次机会用于审查。
两种审查组共享一次真实审查响应，因此每块五次物理修复调用、每组两次有效机会。
该对照比较预算分配架构；每份候选使用同一评测器，但候选数不同，GPU 工作总量不相等。
核验消融同时包含过滤和验证，不单独识别每个提示成分。

## 失败案例说明什么

- 首个 SiLU 回归中，原始审查明确指出漏乘输入并修好；核验组补回因子，却引入
  当前 Triton 不支持的 `tl.expm1`。参考数学正确不等于 API 可执行。
- 第二个 SiLU 种子中，审查员将漏乘输入的 `sigmoid(x0) * x1` 误作参考式，并给出
  精度解释；检查器依据预期数值否决参考式，修复仍未成功。第一个种子的局部收益没有重复。
- 新生成转置中，参考 `transpose(x0)` 通过核验，候选式与实际输出不符被拒绝；
  三组源码仍未通过数值检查。逻辑公式不能代替广播轴、掩码和内存偏移的落实。
- 审查员有时给出合理数学，却使用解释器未支持的语法，造成回退。严格拒绝避免
  将不可验证叙述当事实，但可能损失有用指导；不能由单例推断过滤的因果效果。

这些是完整实验中的具体轨迹，不替换分层结果。源码、回复与具体错误均可在 HTML
选择器中查看。上轮退步的完整拆解见 [失败分析](semantic-failure-analysis.zh.md)。

只为分析输出加入确定性排序，并用倒序遍历测试验证；生成、修复、评测源码未改。

执行快照中；`semantic-analysis-correction.json` 绑定两版哈希并证明其余汇总字段一致。
