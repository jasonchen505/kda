# Kernel agent 复现与改进：实测结论

研究对象是写 kernel 的 agent。KDA 提供提示与任务工作流参考，Humanize 驱动真实
OpenCode 会话，本地 Qwen 生成候选。本项目适配了工作流，没有完整复现 KDA 全部研究
流程，也没有修改 Humanize 上游核心。所有生成源码均由模型提交，未手动修正候选。

## agent 本身的工程改进

控制器按草案、计划、代码保存提案，独立 GPU 进程验证，再决定修复、保留或停止。
FP32/BF16、奇数尺寸、重复调用、输入不变和数值测试组成每次 28 项检查。选择完成后
对选定源码执行新的形状和随机输入检查，结果不反馈给模型。晋升门槛是相对
`torch.compile` 参考的加速几何平均 ≥1.05，最差形状 ≥0.90。

改进包括分类失败反馈、候选 SHA、拒绝陈旧测量、三轮预算、普通模式重复提交终止（固定预算对照仍消耗提案机会并复用测量）、保留最佳
正确候选、带来源的官方示例、修复阶段的短会话，以及局部接口规范化。实际请求表明
只读 proposer 仍被提供 read/webfetch 工具；接口层只移除源码 proposer 的工具声明，
保留后台标题请求。结构化 JSON 中源码字符串丢失换行后，增加逐行字符串数组协议，
控制器仅连接换行，保留缩进，不猜测修复源码。

还修复了控制器的上下文缺口：过去未准入的源码没有进入下一轮修复；现在完整保留
被拒提案并回传，同时把它与已执行候选分开。54 个协议、接口与 Humanize 流程测试
通过，Ruff 通过。机制测试使用替身，不能计入模型成功。

| 2 | 4B 普通反馈 / API 卡，均最多三轮 | 0/8 | 0/8 |
| 3 | 4B 角色提示 + 官方示例 + 短会话 | 0/4 | 0/4 |
| 4a | 4B 原接口 | 1/4 | 0/4 |
| 4b | 4B 去工具声明 | 1/4 | 0/4 |
| 4c | 4B 去工具 + JSON 源码字符串 | 0/4 | 0/4 |
| 5a | 4B 新修复控制器 + JSON 字符串 | 0/4 | 0/4 |
| 5b | 4B 同控制器 + 逐行数组 | 0/4 | 0/4 |
| 6 | 缓存 27B + 最新控制器 + 逐行数组 | 4/4 | 1/4 |
| 7a | 同缓存 27B 无评测反馈，三个提案机会 | 3/3 | 0/3 |
| 7b | 同缓存 27B 有评测反馈，三个提案机会 | 3/3 | 0/3 |
| 独立开发探针 | 4B 向量加法 | 1/1 | 0/1 |

第五阶段字符串与逐行数组分别有 0/12、9/12 个回复通过基本源码准入，但最终正确均为
0/4。它支持“减少协议/语法障碍”的观察，没有显示 GPU 正确率提高。回复轮属于四次
依赖修复运行，不能视为十二次独立成功率试验。两种表示也有不同格式提示和 token 开销。

第六阶段由已有缓存的较大 Qwen FP8 模型生成，GPU4/5 推理、GPU6 评测，温度 0、
seed 20261011、每请求最多 4096 token、每任务最多三轮。没有付费 API、下载新权重
或训练。目录别名 `Qwen3.8-27B-FP8` 的实际配置是 `qwen3_5`；上游权重版本和全量
权重 SHA 未核实。配置、tokenizer/index 指纹与 66 个分片的文件清单已保存。

| 任务 | 候选轮 | 搜索中选定候选加速 | 最终几何平均 | 最终最差形状 | 最终晋升 |
| --- | --- | --- | --- | --- | --- |
| vector_add | 2 | 1.461× | 1.011× | 1.002× | 否 |
| rmsnorm | 3 | 1.092× | 1.031× | 0.878× | 否 |
| softmax | 1 | 1.266× | 1.235× | 1.010× | 是 |
| transpose | 3 | 0.998× | 0.968× | 0.937× | 否 |

四项最终各通过 28 项检查，选中源码核查确认真实执行 Triton kernel，并独立分配输出。
向量加法在反馈后自行把小输入的 block 从 1024 改为 256；搜索时通过门槛，最终形状
上的加速不足，仍被否决。Softmax 的三个最终 BF16 形状为 13×511、96×1025、192×2048；
速度比约为 1.010×、1.205×、1.547×。这是特定参考和尺寸上的单次测量，不是模型推理
端到端加速，也不是通用最优 kernel。

原始各阶段 JSON、提示、回复、候选、独立评测和实际 token 使用均保留。第六阶段
16 份受测源文件与九个候选 SHA 已核对；版本快照在 `results/study6-measured/`。
HTML 将模型能力试验与 4B 消融分开呈现。阶段参与持续开发，不能混合成泛化成功率；
不能将跨模型差异归因于控制器。参考含完整向量加法和其他官方示例，输出属于示例辅助
生成，没有证明独立发明或无参考合成。

## 第七阶段：同模型反馈对照与选择缺陷

两组共享同一缓存模型、参考和三个提案机会。RMSNorm 为开发任务；row_sum 和
silu_mul 在本轮开始前保留为新任务族。各任务各条件运行一次，首轮用户提示逐字一致，
系统工作目录和首轮源码仍不同。没有外部独立基准、种子重复或置信区间。

| 任务 | 无反馈：最终平均 / 最差 | 有反馈：最终平均 / 最差 |
| --- | --- | --- |
| RMSNorm | 0.986× / 0.876× | 0.990× / 0.875× |
| SiLU 乘法融合（新任务） | 0.925× / 0.801× | 0.925× / 0.797× |
| 行求和（新任务） | 0.945× / 0.847× | 0.942× / 0.848× |

两组最终各 3/3 正确、0/3 晋升，两个新任务在两组各 2/2 正确。无反馈 / 有反馈各
9 次提案中有 4 / 8 份不同源码 SHA、5 / 1 次重复；不同 SHA 包括注释变化，不等于
不同算法。输出 token 为 5482 / 5536，流程总秒数约 1124.9 / 1396.4，包含额外候选
评测和审计成本。共有 12 份唯一源码：11 份搜索正确并接受最终检查、1 份数值失败。
这些计数支持执行与追踪能力，没有证明反馈提高最终成功率。

关键发现是候选选择与验收口径不一致。SiLU 反馈组：

| 候选 | 搜索平均 / 最差 | 搜索晋升 | 最终平均 / 最差 | 原选择 |
| --- | --- | --- | --- | --- |
| 首轮 BLOCK=1024 | 1.3366× / 0.773× | 否 | 0.925× / 0.797× | 选中 |
| 第二轮 BLOCK=256 | 1.3354× / 0.998× | 是 | 1.287× / 0.990× | 丢弃 |

原控制器只比较正确候选的平均加速，因此略高但最差形状不达门槛的首轮挤掉了第二轮。
第三轮重复首轮。问题来自 agent 的决策，而非手动改写 kernel。

已经实现门槛优先：正确候选中，满足已有两项性能门槛的候选优先，再比较平均加速，
严格比较保留稳定平局；最终检查仍能否决。新增流程回归验证该失败模式及旧规则
兼容，共 53 项测试通过。原计划 runner 显式保留旧 geomean 规则，当前默认控制器
使用修正规则；阶段七的 16 份受测源文件和 18 份提案已冻结保存。

在相同已有候选集上，只利用搜索结果选择、再查原最终审计，门槛优先为反馈组 1/3
晋升、无反馈 0/3。**这是发现缺陷后的事后规则审计，没有重新生成，不是新的独立
验证，也没有改变原实验 0/6 晋升。** 首轮、末轮、搜索最优的原审计均 0/6 晋升。
行求和反馈组末轮的最终值比搜索最优更好，也说明搜索排名未必转移到最终形状。

为检查这不是一次偶然最终计时，又对这两份冻结的 SiLU 源码各启动三次新的 GPU6
评测进程。原选中首轮是 3/3 正确、0/3 晋升，平均加速 0.926–0.932×、最差
0.802–0.816×；被丢弃的第二轮是 3/3 正确、3/3 晋升，平均 1.289–1.299×、最差
0.996–1.005×。源码 SHA 与评测响应逐次核对。这是固定候选的测量复核，不调用模型、
不重新选择，也不能替代修正规则下的新模型生成验证。

## 求职表述与下一步

可如实写：基于 KDA/Humanize 实现本地 Qwen 驱动的 Triton kernel agent，搭建独立
数值与性能评测、分类修复、预算控制、SHA 追踪和候选选择闭环；完成六次同预算策略
对照与两类提前保留的新任务验证，从完整轨迹定位并修复“平均排序丢弃满足门槛候选”
的决策缺陷，并以六次固定候选重评测复核测量差异，交付离线交互 HTML、原始结果、
源码快照和 54 项机制与接口检查；另完成修正规则下的三次真实生成复现，最终
3/3 正确、2/3 晋升。具体口径见 `docs/selector-validation-results.md`。

面试重点是问题、方法、对照、失败发现与修复。不能将事后审计写成独立 A/B 收益，
不能写“稳定高成功率”“反馈显著提升正确率”或“达到 SOTA”。修正规则的新生成
复现已完成；下一步重复多个独立种子，再扩展任务集与 profiler 反馈。当前仍没有
多种子可靠性或广泛泛化结论。
AST 准入只是防错检查，不是安全沙箱。上游 Humanize 先前完整套件仍有 17 个失败。
